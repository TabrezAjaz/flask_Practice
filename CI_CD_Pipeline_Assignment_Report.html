Application

Python Flask CRUD application for student records. Flask-PyMongo connects to MongoDB in live environments. Gunicorn runs the deployed service behind a local port.

Test Isolation

The inherited tests required a real MongoDB daemon. They now inject mongomock.MongoClient, giving repeatable tests on Jenkins and GitHub-hosted runners.

Release Model

Each run creates student-registration.tar.gz. The server expands it into a numbered release, installs runtime dependencies, and atomically updates the current link.

Verification

After systemd restart, deployment calls http://127.0.0.1:8000/health. A non-200 response fails the deployment instead of reporting a false success.

2. Jenkins CI/CD Pipeline

The root Jenkinsfile is a declarative pipeline. Jenkins checks out the fork from SCM and responds to GitHub push webhooks through githubPush().

StageImplementationFailure Behavior
BuildCreate virtual environment, install requirements-dev.txt, and package a tar artifact.Dependency or packaging error stops the run.
TestRun pytest -q --junitxml=test-results.xml.Any failed test blocks deployment.
Deploy to StagingOn main, bind SSH credentials and run the shared deployment script.SSH, service restart, or health-check error fails the run.
PostPublish JUnit, archive artifact, and send success/failure email through Email Extension.Result remains visible in Jenkins even if notification is disabled.

Required Jenkins Configuration

  1. Ubuntu VM with Java 21, Jenkins, Git, Python 3, and python3-venv.
  2. Plugins: Pipeline, Git, GitHub Integration, Credentials Binding, JUnit, and Email Extension.
  3. Secret text credential staging-host.
  4. SSH private-key credential staging-ssh.
  5. SMTP details in Extended E-mail Notification.
  6. GitHub webhook ending in /github-webhook/, push events enabled.
Notification rule: the job parameter NOTIFICATION_EMAIL supplies the recipient. The post success and post failure blocks send different subjects and include the build URL.

4. Deployment Environment

The one-time scripts/install-service.sh installer creates the release directory and a systemd unit. Runtime secrets remain on the VM in /etc/student-registration.env.

sudo apt-get install -y python3 python3-venv curl
bash scripts/install-service.sh /opt/student-registration "$USER"

# /etc/student-registration.env (values omitted from Git)
MONGO_URI=mongodb+srv://...
SECRET_KEY=...

Deployment Sequence

  1. Confirm the build artifact exists.
  2. Copy it over SSH to a unique temporary path.
  3. Create a release directory using the CI run/build number.
  4. Extract source and create an isolated Python virtual environment.
  5. Install runtime-only dependencies.
  6. Update the current symlink.
  7. Restart only student-registration.service.
  8. Retry the health endpoint up to five times and fail if unavailable.
Least privilege: the deployment user needs only SSH access, write access to the application directory, and passwordless permission for systemctl restart student-registration.
